⚠ Verification Finding: Navigation Property ขาด — ต้องแก้ไข

DAL model RequisitionTemporaryItemDetail มีอยู่แล้ว แต่ไม่มี FK navigation property เชื่อมกลับไปหา Requisition ทำให้ EF Core ไม่สร้าง relationship

Fix 1: เพิ่ม navigation property ใน RequisitionTemporaryItemDetail.cs

// RequisitionTemporaryItemDetail.cs public int RequisitionId { get; set; } // ADD: Navigation property [ForeignKey("RequisitionId")] public virtual Requisition Requisition { get; set; }

Fix 2: เพิ่ม collection navigation ใน Requisition.cs

// Requisition.cs // ADD: Collection navigation property public virtual ICollection<RequisitionTemporaryItemDetail> RequisitionTemporaryItemDetails { get; set; }
⚠ Transit Fields ยังขาดใน Option A

Option A ปัจจุบันครอบคลุมเฉพาะ Import/Export เท่านั้น ยังไม่มี Transit-specific columns:

  • TransitFromCountryId (INT NULL FK) — ประเทศต้นทาง
  • TransitToCountryId (INT NULL FK) — ประเทศปลายทาง
  • TransitRoute (NVARCHAR(500)) — เส้นทางนำผ่าน
  • CustomsCheckpoint1 (NVARCHAR(255)) — ด่านศุลกากร 1
  • CustomsCheckpoint2 (NVARCHAR(255)) — ด่านศุลกากร 2

ทางเลือก: (1) เพิ่ม 5 columns เหล่านี้ใน Requisition table ด้วย (ALTER TABLE เพิ่มเป็น 9 columns) หรือ (2) ใช้ Option C สำหรับ Transit โดยแยกเป็น RequisitionTransit table

ข้อดี
  • ใช้ Requisition table เดิม — ไม่ต้องสร้างตารางหลักใหม่
  • RequisitionForeignEntity มี DAL แล้ว — แค่เพิ่ม Z4 mapping
  • Query ง่าย — JOIN กับ Requisition ตรง
  • คำขอปกติ + เฉพาะคราว อยู่ใน table เดียว — report ง่าย
  • ALTER TABLE เพิ่มแค่ 4 columns
ข้อเสีย
  • Requisition table มี columns เยอะขึ้น (46 → 50)
  • columns เฉพาะคราว จะเป็น NULL ในคำขอปกติ
  • ต้องสร้าง DAL model ใหม่สำหรับ RequisitionTemporaryItemDetail

Option C: Hybrid — ใช้เดิม + แยกเฉพาะ Transit ทางเลือก

Effort: กลาง

Import/Export ใช้ columns เดิมใน Requisition | Transit สร้างตาราง RequisitionTransit แยก

Import/Export → Requisition เดิม
  • TransportTypeId ✅ มีอยู่
  • ExportPortId ✅ มีอยู่
  • EntryPortId ✅ มีอยู่
  • ImportAuthorizationNo → เพิ่ม
  • ImportAuthDate → เพิ่ม
  • ImportAuthAgency → เพิ่ม
Transit → RequisitionTransit (ใหม่)
  • TransitFromCountryId
  • TransitToCountryId
  • TransitRoute
  • CustomsCheckpoint1/2
  • ValidityStartDate/EndDate
  • PermitType (N/R/A)
  • AmendmentDetails
ข้อดี
  • Import/Export ง่าย — ใช้ columns ที่มี + เพิ่มน้อย
  • Transit แยกชัด — structure ต่างมาก
  • Best of both worlds
ข้อเสีย
  • Logic ซับซ้อนขึ้น — ต้อง check ว่าเป็น IMP/EXP หรือ Transit
  • 2 patterns ใน codebase
